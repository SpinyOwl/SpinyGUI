**Changes:**

  selector, layout, transform, render, and allocation scaling.

  or text boundaries, paint-only hover, dimension-affecting hover, keyboard-only input, scroll,
  click/focus, text editing, resize, and unknown listener effects.

### T2: Implement conservative interaction invalidation

**Purpose:** Avoid full style/layout work for proven no-impact and paint-only pointer cases while
retaining correct geometry changes and unknown fallbacks.

**Changes:**

- Preserve E6/M1.5 behavior: stable inert movement may be `UNCHANGED`, while boundary transitions,
  pointer consumers, focus/pressed/edit/scroll effects, and unknown listeners remain conservative.
- Add an explicit internal or opt-in orchestration boundary that can distinguish proven no-impact,
  paint-only hover, layout-affecting hover, and full/unknown refresh without weakening the existing
  binary public result used by Rogue.
- A no-impact pointer batch must execute neither full style recalculation nor layout.
- A hover transition may skip layout only after SpinyGUI proves that every resulting style change is
  paint-only. If the proof is incomplete, fall back to layout.
- Dimension, flow, font-metric, overflow/scrollbar, positioning, or transform-affecting hover changes
  must run the required layout/transform work.
- Avoid new per-event collections and remove avoidable hot-path temporary allocation where ownership
  is clear; do not introduce unsafe cached hit paths or geometry without invalidation proof.
- Keep render traversal immediate-mode in this slice; count it and report it rather than masking it.

**Acceptance checks:**

- Regression tests prove the optimized decisions and final frame state equivalent to force-full
  execution for hover, focus, click, scroll, text editing, resize, and dimension-affecting hover.
- Unknown listener/event effects always take full fallback.
- Stable same-target motion delivers the same events/state as before and does not request full
  style/layout.

## Risks

- Paint-vs-layout property classification can silently under-invalidate. Unknown or unsupported
  properties must force layout/full fallback.
- A cached hit path can become stale after scroll, resize, transforms, structure, or overlapping
  geometry. Do not skip hit testing without an observable invalidation generation and equivalence
  tests.
- Timing with counters enabled can distort the result. Keep structural characterization separate
  from accepted timing/allocation samples.
- The current dirty worktree is shared and large; stage/commit operations are out of scope and
  unrelated changes must remain untouched.
